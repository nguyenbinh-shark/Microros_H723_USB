💡1. micro-ROS là gì & tại sao quan trọng?

Hãy tưởng tượng bạn có một board STM32 gắn cảm biến IMU và motor. Bạn muốn đưa dữ liệu cảm biến vào ROS 2 (hệ điều hành robot) để dùng rviz trực quan, ghi ros2 bag, hay chạy Nav2 tự hành. Câu hỏi là: làm sao board "nói chuyện" được với ROS 2?

micro-ROS chính là câu trả lời. Nó là một phiên bản ROS 2 thu nhỏ chạy được ngay trên vi điều khiển (MCU). Khi cài micro-ROS lên STM32, board của bạn tự động trở thành một node ROS 2 thật —-publish/subscribe đúng các kiểu message chuẩn như sensor_msgs/Imu, geometry_msgs/Twist... — mà không cần phải "bịa" ra giao thức riêng.


   "CÁCH CŨ" — tự bịa giao thức qua UART                   micro-ROS — ROS 2 native

   ┌─────────┐  UART    ┌──────────────┐                  ┌─────────┐  UART   ┌─────────┐  DDS   ┌─────────┐
   │  STM32  │─────────▶│  Script PC   │                  │  STM32  │────────▶│  Agent  │◀──────▶│  ROS 2  │
   │ print() │ "12.3\n" │  parse chuỗi │                  │rcl_pub()│  XRCE   │ (bridge)│        │  network│
   └─────────┘          └──────────────┘                  └─────────┘         └─────────┘        └─────────┘
        ❌ tự nghĩ format, đổi thông điệp = sửa cả 2 nơi         ✅ đúng sensor_msgs/Imu, "ros2 echo" chạy luôn
🔑
Ý chính trong 1 câu

micro-ROS biến MCU thành một node ROS 2 chính hiệu, dùng đúng message chuẩn. Bạn không phải tự thiết kế giao tiếp — ROS 2 lo phần đó.

⚖️2. Vì sao chọn micro-ROS? (so sánh các phương án)

Đưa MCU vào ROS 2 không chỉ có một cách. Bảng dưới so sánh 3 hướng phổ biến để bạn thấy micro-ROS thắng ở đâu:

① UART/CAN thô

MCU printf chuỗi, PC tự parse.

đơn giản ban đầu không chuẩn

Đổi message → sửa firmware và script. Không có QoS, service, timestamp...

② rosserial

Thư viện cũ, phổ biến thời ROS 1.

ROS 1 gốc ít duy trì

Cổng sang ROS 2 sơ sài, hiệu năng và độ tin cậy kém hơn micro-ROS.

③ micro-ROS ✅

Client ROS 2 native cho MCU.

ROS 2 chuẩn QoS / service

Dùng DDS-XRCE, ros2 tools chạy luôn, hỗ trợ nhiều transport & MCU.

Bí mật: DDS-XRCE & "Agent bridge"

ROS 2 giao tiếp bằng DDS — một giao thức khá "nặng" cho MCU bé nhỏ. micro-ROS dùng một biến thể nhẹ hơn tên XRCE (eXtremely Resource-Constrained Environment). MCU chỉ gửi/nhận các thông điệp nhỏ; phần "nặng" của DDS được một chương trình trên PC tên Agent gánh hộ. Nhờ vậy MCU vừa được "ROS 2 thật", vừa không bị quá tải.

🤝
Đổi lại (thỏa hiệp)

Phải chạy Agent trên một máy PC/Pi; phải build trước thư viện tĩnh micro-ROS; và có giới hạn số node/publisher cấu hình sẵn cho MCU. Đó là cái giá hợp lý để đổi lấy "ROS 2 native".

🏗️3. Kiến trúc 3 lớp — hiểu trong 1 phút

Toàn bộ hệ thống chỉ có 3 lớp nối với nhau. Hiểu được ảnh dưới là bạn đã nắm 80% bài toán:


   ┌───────────────────────────────┐        ┌──────────────────────────┐        ┌────────────────────┐
   │ LỚP 1 — CLIENT (trên MCU)     │  UART  │ LỚP 2 — AGENT (trên PC)  │  DDS   │ LỚP 3 — ROS 2 /    │
   │ STM32H723 + FreeRTOS          │◀──────▶│  micro_ros_agent         │◀──────▶│ DDS network        │
   │                               │ 115200 │                          │  UDP   │                    │
   │ • node "stm32h7_node"         │ CH340  │ • dịch XRCE ↔ DDS        │        │ • /imu /odom ...    │
   │ • publish /imu /odom ...      │        │ • chạy trong WSL2 / Pi    │        │ • ros2 topic echo   │
   │ • subscribe /cmd_vel          │        │                          │        │ • rviz · Nav2 · bag │
   └───────────────────────────────┘        └──────────────────────────┘        └────────────────────┘

Ví dụ một luồng dữ liệu (từ cảm biến đến màn hình)


   BMI088 ──▶ Mahony (lọc góc) ──▶ quaternion ──▶ rcl_publish("/imu") ──▶ Agent ──▶ DDS ──▶ ros2 topic echo /imu
  • Lớp 1 (Client): chính là firmware trên STM32 (code trong freertos.c). Nó tạo node, publish/subscribe.
  • Lớp 2 (Agent): một tiến trình bạn chạy trên PC, làm cầu nối serial ↔ DDS.
  • Lớp 3 (ROS 2): mạng ROS 2 tiêu chuẩn — mọi lệnh ros2, rviz, Nav2 đều ở đây.

Transport (đường truyền) trong project này là UART ở 115200 bps qua mạch CH340 USB-serial, ra cổng /dev/ttyUSB0 trên PC.

🟦5. Bước 1 — Cài Agent micro-ROS (chỉ làm 1 lần)

Agent là chương trình chạy trên PC làm cầu nối (Lớp 2 ở mục 3). Bạn cài nó một lần duy nhất từ kho micro_ros_setup.

Yêu cầu: Ubuntu 24.04 đã cài ROS 2 Jazzy. Nếu dùng Windows, chạy Ubuntu trong WSL2 (cách forward USB xem mục 6). Trên Raspberry Pi/Linux native thì làm y hệt, chỉ khác là không cần forward USB.

bash · terminal Ubuntu/WSL2# Tạo workspace và lấy bộ cài micro-ROS (nhánh Jazzy)
mkdir -p ~/microros_ws/src && cd ~/microros_ws
git clone -b jazzy https://github.com/micro-ROS/micro_ros_setup.git src/micro_ros_setup

# Cài dependencies
sudo apt update && rosdep update
rosdep install --from-paths src --ignore-src -y

# Build workspace micro_ros_setup
colcon build
source install/local_setup.bash

# Tạo và build Agent (tải mã nguồn Agent + biên dịch)
ros2 run micro_ros_setup create_agent_ws.sh
ros2 run micro_ros_setup build_agent.sh
source install/local_setup.bash
⏳
Kiên nhẫn nhé

Lệnh build_agent.sh tải và biên dịch cả một stack DDS nên có thể mất nhiều phút. Đợi tới khi xong là bình thường, không phải treo máy.

🟩6. Bước 2 — Kết nối & chạy Agent (mỗi lần dùng)

Đây là chuỗi thao tác bạn làm mỗi lần muốn dùng board. Làm đúng thứ tự:

  1. Cắm cáp CH340 từ board vào PC. Board tự khởi động (dùng offset hiệu chỉnh sẵn trong firmware, không cần giữ phẳng).
  2. Trên Windows — forward USB vào WSL2 (mở PowerShell dạng Administrator): 
    powershell · Adminusbipd list                       # tìm dòng CH340, ví dụ busid 1-2
usbipd attach --wsl --busid 1-2   # đẩy USB đó vào WSL
    🐧
    Dùng Raspberry Pi / Linux native?

    Bỏ qua bước này — board đã hiện luôn ở /dev/ttyUSB0.

  3. Trong WSL2 — cấp quyền & chạy Agent (terminal #1): 
    bash · WSL2 · terminal #1sudo chmod 666 /dev/ttyUSB0
source ~/microros_ws/install/setup.bash
ros2 run micro_ros_agent micro_ros_agent serial --dev /dev/ttyUSB0 -b 115200
  4. Đợi dòng [3/3] Session established! xuất hiện —— rồi NHẤN NÚT RESET trên board STM32. (Firmware chủ động đồng bộ phiên lúc khởi động, nên cần reset sau khi Agent đã sẵn sàng.)
🔍
Không biết cổng nào? ttyUSB0 hay ttyACM0?

Tùy loại cáp USB-serial mà board hiện /dev/ttyUSB0 hoặc /dev/ttyACM0. Kiểm tra nhanh:

ls /dev/ttyUSB* /dev/ttyACM*

rồi thay cổng tương ứng vào lệnh Agent. Baud luôn là 115200.

🟦8. Bước 4 — Kiểm tra trên ROS 2

Mở terminal #2 (cũng đã chạy source ~/microros_ws/install/setup.bash) và thử các lệnh:

bash · WSL2 · terminal #2ros2 node list          # phải thấy: /stm32h7_node
ros2 topic list         # phải thấy: /imu /euler /motor_fb /odom /cmd_vel
ros2 topic echo /imu     # quaternion + gyro + accel
ros2 topic echo /euler   # roll/pitch/yaw (đơn vị độ)
ros2 topic hz /imu       # tần số publish ≈ 50 Hz
TopicKiểu messageHzNội dung
/imusensor_msgs/Imu50Quaternion · gyro (rad/s) · gia tốc (m/s²)
/eulergeometry_msgs/Vector350Roll · Pitch · Yaw (độ)
/motor_fbsensor_msgs/JointState50Vị trí (rad) · vận tốc (rad/s) motor ID 1
/odomnav_msgs/Odometry50Pose (dead-reckoning) · twist (đã lọc Kalman)
/cmd_velgeometry_msgs/Twist—lệnh điều khiển ← subscribe

Giá trị "bình thường" khi board đặt phẳng

/euler

x ≈ 0°, y ≈ 0°, z = yaw tùy hướng.
Lưu ý: nhảy loạn trong ~3 giây đầu (bộ lọc chưa hội tụ) — chờ ins_flag = 1 rồi mới tin.

/imu

angular_velocity: |x|,|y|,|z| < 0.05 rad/s.
linear_acceleration: z ≈ 9.81 m/s² (trọng lực).

🎮9. Lái robot bằng bàn phím (teleop)

Project kèm sẵn script teleop/teleop_key.py — một script Python (rclpy) xuất bản lệnh lên /cmd_vel khi bạn bấm phím. Chạy nó ở terminal #2 (đã source):

bash · WSL2 · terminal #2python3 teleop/teleop_key.py            # mặc định an toàn
python3 teleop/teleop_key.py --step 0.05   # bước nhỏ cho người mới
PhímTác dụng
w / stăng / giảm tuyến tiến (linear)
a / dquay trái / phải (angular)
spacedừng ngay lập tức
+ / -to / nhỏ bước điều khiển
q / Ctrl-Cthoát (luôn gửi lệnh dừng trước)

Có cơ chế deadman: nếu bạn không bấm phím trong 0.5 giây, lệnh tự động về 0 — tránh robot chạy tự do.

⛔
Quan trọng — đọc trước khi lái!

Hiện tại firmware hiểu linear.x / angular.z trực tiếp thành moment lực (Nm) trên motor CyberGear, chưa phải vận tốc (m/s, rad/s). Đây là lỗi chưa sửa (đánh dấu "#4" trong teleop/README.md; code thực tế ở User/APP/motor_task.c). Hệ quả: robot có thể giật mạnh nếu bước lớn. Luôn bắt đầu với --step nhỏ và đứng sẵn để bấm space.

📖10. Đọc hiểu firmware micro-ROS tối thiểu

Toàn bộ node ROS 2 nằm trong hàm StartDefaultTask ở file Core/Src/freertos.c. Đây là "bộ xương" micro-ROS tối thiểu mà bạn có thể học theo:

① Đăng ký transport (đường truyền)

freertos.crmw_uros_set_custom_transport(
  true,
  (void *) &huart7,                 # ← UART7, chính là CH340 115200
  cubemx_transport_open,
  cubemx_transport_close,
  cubemx_transport_write,
  cubemx_transport_read);

② Cấp bộ cấp phát (allocator) thân thiện FreeRTOS

MCU không cho phép malloc lung tung, nên ta cắm các hàm cấp phát của riêng mình (microros_allocate...) để micro-ROS dùng heap của FreeRTOS một cách kiểm soát.

③ Khởi tạo node + đồng bộ

freertos.crclc_support_init(&support, 0, NULL, &allocator);
rmw_uros_sync_session(1000);                            # bắt tay với Agent
rclc_node_init_default(&node, "stm32h7_node", "", &support);

④ Tạo publisher / subscriber

freertos.c# ví dụ 1 publisher /imu
rclc_publisher_init_default(
  &pub_imu, &node,
  ROSIDL_GET_MSG_TYPE_SUPPORT(sensor_msgs, msg, Imu),
  "imu");

# và 1 subscriber /cmd_vel
rclc_subscription_init_default(
  &sub_cmd_vel, &node,
  ROSIDL_GET_MSG_TYPE_SUPPORT(geometry_msgs, msg, Twist),
  "cmd_vel");

⑤ Executor + vòng lặp publish 50 Hz

freertos.c# Executor chỉ có 1 handle (subscriber /cmd_vel)
rclc_executor_init(&executor, &support.context, 1, &allocator);
rclc_executor_add_subscription(&executor, &sub_cmd_vel, &cmd_vel_msg,
  &cmd_vel_callback, ON_NEW_DATA);

for (;;) {
  rclc_executor_spin_some(&executor, RCL_MS_TO_NS(10));   # xử lý /cmd_vel (non-blocking)

  uint32_t now = HAL_GetTick();
  if ((now - last_pub_ms) >= 20U) {                        # gate 20 ms → 50 Hz
    last_pub_ms = now;
    # ... đổ dữ liệu vào imu_msg, euler_msg, motor_fb_msg, odom_msg ...
    rcl_publish(&pub_imu, &imu_msg, NULL);
  }
}

Static buffer — tránh heap

Các mảng động trong message (ví dụ JointState.position) được trỏ vào mảng static khai báo sẵn, để micro-ROS không phải cấp phát động lúc chạy.

Covariance = −1

Theo quy ước REP-145, đặt covariance[0] = -1 nghĩa là "không biết độ lệch". Cách viết chuẩn, không phải bug.

🛠️11. Lỗi thường gặp & cách sửa

Hiện tượngNguyên nhânCách sửa
WSL không thấy /dev/ttyUSB0 Chưa forward USB / sai busid Chạy usbipd list → usbipd attach --wsl --busid X-X (PowerShell Admin)
Agent không ra Session established Sai cổng/baud; chưa RESET board; firmware chưa chạy Kiểm ls /dev/ttyUSB*, baud 115200; đảm bảo đã nhấn RESET sau khi Agent chạy
ros2 topic list trống Terminal echo chưa source; hoặc sai ROS_DOMAIN_ID Chạy source ~/microros_ws/install/setup.bash; đặt cùng ROS_DOMAIN_ID=0 ở 2 terminal
/euler nhảy loạn 3 giây đầu Bộ lọc Mahony chưa hội tụ Bình thường — chờ ins_flag = 1 (~3 s) rồi mới tin giá trị
Motor không chạy /cmd_vel = 0 nên enable = 0; hoặc bước quá nhỏ Gửi linear.x ≠ 0 hoặc angular.z ≠ 0; nhớ cảnh báo torque-vs-velocity ở mục 9
Robot giật mạnh khi teleop Firmware dùng trực tiếp cmd_vel làm moment lực (Nm) Dùng --step thật nhỏ; đứng sẵn bấm space
Build lỗi thiếu libmicroros.a Chưa build thư viện tĩnh micro-ROS (bị gitignore) Theo script Docker trong micro_ros_stm32cubemx_utils/ để sinh lib

✅12. Tóm tắt & đi tiếp đâu

3 điều cần nhớ

  1. micro-ROS = ROS 2 native trên MCU; board thành một node ROS 2 thật, dùng đúng message chuẩn.
  2. Cần một Agent chạy trên PC làm cầu nối serial ↔ DDS (phần nặng gánh ở PC).
  3. Transport project này là UART 115200 qua CH340 → /dev/ttyUSB0.
