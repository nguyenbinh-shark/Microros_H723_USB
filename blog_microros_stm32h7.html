⚙️Thiết kế FreeRTOS tối ưu

Đây là phần quan trọng nhất của cả project. Chia task đúng quyết định tính thời gian thực, độ ổn định và khả năng mở rộng của hệ thống.

Nguyên tắc cốt lõi khi thiết kế task

① Phân loại theo độ trễ chấp nhận được

Đặt câu hỏi: "Nếu task này trễ 1ms, hệ thống có bị hỏng không?"

  • Hard real-time: Trễ là thảm họa → priority cao nhất
  • Soft real-time: Trễ chấp nhận được → priority trung bình
  • Best-effort: Chậm không sao → priority thấp

② Mỗi task làm đúng một việc

Không nhét nhiều chức năng vào 1 task. Lý do:

  • Dễ debug từng phần độc lập
  • Mỗi task có deadline riêng, tối ưu priority riêng
  • Tránh blocking task quan trọng vì việc phụ

③ Stack size đủ dùng, không lãng phí

Stack quá nhỏ → stack overflow (crash). Quá lớn → lãng phí RAM. Công thức tính:

Stack = call_depth × frame_size + local_vars + interrupt_frame

Dùng uxTaskGetStackHighWaterMark() để đo thực tế.

④ osDelay() là điểm nhường CPU

Sau mỗi osDelay(N), task nhường CPU cho task có priority thấp hơn chạy. Không có osDelay → task chiếm CPU 100%, không task nào khác chạy được.

Priority của 4 task trong dự án

REALTIME
INS_Task — Mahony filter, BMI088 read, 1ms deadline
HIGH
OBSERVE_Task — placeholder, reserved cho sensor fusion sau này
ABOVE NORMAL
MOTOR_Task — FDCAN CyberGear, 10ms loop
NORMAL
defaultTask — micro-ROS publish/subscribe, 20ms loop

Tại sao INS_Task phải là Realtime?

Bộ lọc Mahony tích phân phương trình vi phân quaternion theo thời gian. Nếu vòng lặp không đều:

dt thực tế = 1.5ms thay vì 1ms → sai số tích lũy 50% mỗi vòng → sau 100 vòng (100ms) góc sai ~5°

Ở Realtime priority, INS_Task chỉ bị preempt bởi interrupt phần cứng (DMA, FDCAN) — không bị task nào chen. Điều này đảm bảo dt luôn ổn định ~1ms.

Vòng lặp của từng task

/* ── INS_Task: 1ms, hard real-time ─────────────────────── */
void INS_task(void) {
    INS_Init();
    DWT_GetDeltaT(&INS_DWT_Count);    /* reset timer */
    while(1) {
        ins_dt = DWT_GetDeltaT(&INS_DWT_Count);
        if (ins_dt > 0.01f) ins_dt = 0.001f;
        BMI088_Read(&BMI088);
        mahony_update(&mahony);          /* ~20 µs */
        osDelay(1);                       /* nhường CPU 1ms */
    }
}

/* ── OBSERVE_Task: Kalman velocity observer, 3ms ───────── */
void Observe_task(void) {
    while (INS.ins_flag == 0) { osDelay(1); }  /* chờ AHRS hội tụ */
    velKF_Init();
    for (;;) {
        /* Encoder: tốc độ bánh → tốc độ robot */
        float v_left  = CAN_GetMotorVel(1) * MOTOR_LEFT_SIGN  * WHEEL_RADIUS;
        float v_right = CAN_GetMotorVel(2) * MOTOR_RIGHT_SIGN * WHEEL_RADIUS;
        float v_odom  = (v_left + v_right) * 0.5f;
        /* IMU: gia tốc chiều tiến */
        float a_imu   = INS.MotionAccel_b[0];
        /* Kalman update: fuse encoder + IMU accel */
        velKF_Update(v_odom, a_imu);
        Observe.v_filter     = vel_acc[0];   /* vận tốc slip-resistant */
        Observe.omega_filter = INS.Gyro[2];  /* yaw rate rad/s */
        osDelay(3);
    }
}

/* ── MOTOR_Task: 10ms, điều khiển FDCAN ────────────────── */
void Motor_Task_Entry(void *arg) {
    FDCAN1_Config(); FDCAN2_Config();
    osDelay(3000);                     /* chờ IMU hội tụ 3s */
    while(1) {
        osMutexAcquire(g_cmd_mutex, osWaitForever);
        cmd = g_robot_cmd;
        osMutexRelease(g_cmd_mutex);
        mit_ctrl(&hfdcan1, ...);          /* gửi lệnh CyberGear */
        osDelay(10);                      /* 10ms = 100 Hz */
    }
}

/* ── defaultTask: 20ms, micro-ROS publish ──────────────── */
void StartDefaultTask(void *arg) {
    /* ... init micro-ROS ... */
    while(1) {
        rclc_executor_spin_some(&executor, RCL_MS_TO_NS(10));
        if ((now - last) >= 20U) {
            rcl_publish(&pub_imu, ...);   /* 50 Hz = mỗi 20ms */
            rcl_publish(&pub_euler, ...);
        }
    }
}

⚠️

Thư viện micro-ROS chứa nhiều lớp: RCL → RCLC → rmw → uxr client → UART transport. Mỗi lớp thêm stack frame. Dưới 8KB → crash ngẫu nhiên. Nên dùng 12KB (3000 words) trở lên.

🔗Giao tiếp giữa các task

Khi nhiều task cùng đọc/ghi một biến, cần cơ chế đồng bộ để tránh race condition.

Vấn đề race condition

/* ❌ SAI — không bảo vệ shared variable */
/* INS_Task viết: */   INS.Roll = mahony.roll;
/* defaultTask đọc: */ euler_msg.x = INS.Roll;
/* Nếu INS_Task bị preempt GIỮA CHỪNG khi đang viết → defaultTask đọc giá trị lỗi! */
C
💡
Tại sao không crash trong dự án này?

Trong Cortex-M7, ghi float (32-bit) vào aligned address là atomic — không bị ngắt giữa chừng. Nên đọc/ghi biến float đơn lẻ như INS.Roll vẫn an toàn. Nhưng khi đọc struct lớn (quaternion 4 floats) cần mutex!

Mutex — Bảo vệ dữ liệu chia sẻ

Mutex (MUTual EXclusion) đảm bảo chỉ 1 task được truy cập vào vùng dữ liệu tại một thời điểm:

/* ── Khai báo ── */
osMutexId_t g_cmd_mutex;
g_cmd_mutex = osMutexNew(NULL);   /* tạo trong MX_FREERTOS_Init() */

/* ── MOTOR_Task đọc lệnh (consumer) ── */
osMutexAcquire(g_cmd_mutex, osWaitForever);
cmd = g_robot_cmd;               /* copy an toàn */
osMutexRelease(g_cmd_mutex);

/* ── defaultTask (callback) ghi lệnh (producer) ── */
void robot_cmd_set(float vel, float yaw, float torq, uint8_t en) {
    osMutexAcquire(g_cmd_mutex, osWaitForever);
    g_robot_cmd.velocity = vel;
    g_robot_cmd.yaw_rate = yaw;
    g_robot_cmd.enable   = en;
    osMutexRelease(g_cmd_mutex);
}

⏱️DWT — Đo thời gian chính xác nano-giây

HAL_GetTick() chỉ có độ phân giải 1ms — quá thô cho bộ lọc Mahony cần biết dt = 0.001s chính xác. DWT cho độ phân giải 1/550MHz ≈ 1.8 nano-giây.

Cách DWT hoạt động


  CPU Clock: 550 MHz

  Mỗi clock cycle = 1/550,000,000 s ≈ 1.8 ns

  DWT->CYCCNT: thanh ghi 32-bit, tự động đếm số cycle
               tràn sau: 2^32 / 550MHz ≈ 7.8 giây
               (uint32 overflow → tự wrap around, phép trừ vẫn đúng!)

  dt = (CYCCNT_now - CYCCNT_last) / 550,000,000
     = số cycle đã trôi qua / tần số
     = thời gian thực (giây)

  Ví dụ:
    CYCCNT_last = 0
    CYCCNT_now  = 550,000    (sau 1ms)
    dt = 550,000 / 550,000,000 = 0.001 s = 1ms ✓

/* ── bsp_dwt.c ────────────────────────────────────────── */

void DWT_Init(uint32_t CPU_Freq_mHz) {
    CPU_FREQ_Hz = CPU_Freq_mHz * 1000000UL;
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;  /* bật DWT */
    DWT->CYCCNT = 0;                                /* reset counter */
    DWT->CTRL   |= DWT_CTRL_CYCCNTENA_Msk;          /* enable counting */
}

float DWT_GetDeltaT(uint32_t *cnt_last) {
    volatile uint32_t cnt_now = DWT->CYCCNT;
    float dt = ((uint32_t)(cnt_now - *cnt_last)) / ((float)CPU_FREQ_Hz);
    *cnt_last = cnt_now;
    return dt;
    /* (uint32_t) cast đảm bảo overflow 32-bit được xử lý đúng */
}

/* ── Sử dụng trong main.c ─────────────────────────────── */
DWT_Init(550);            /* PHẢI gọi trước RTOS! */
BMI088_init(&hspi2, 0);   /* init BMI088 */
osKernelStart();

Tại sao gọi DWT_Init trong main.c chứ không trong task?

DWT là tài nguyên phần cứng dùng chung toàn hệ thống. Khởi động sớm trong main.c đảm bảo nó sẵn sàng trước khi bất kỳ task nào chạy, tránh race condition khi nhiều task cùng cần DWT.

🧭Bộ lọc Mahony — Nguyên lý & tham số

Mahony AHRS là thuật toán ước lượng hướng (attitude) kết hợp gyroscope và accelerometer bằng phương pháp phản hồi tỉ lệ-tích phân (PI).

Tại sao cần kết hợp cả hai sensor?

SensorƯu điểmNhược điểm
GyroscopeNhanh nhạy, ít nhiễu ngắn hạn, đo được YawDrift: ZRO (Zero Rate Output) tích lũy theo thời gian
AccelerometerTham chiếu trọng lực dài hạn không driftNhiễu khi chuyển động, không đo được Yaw
MahonyKết hợp tốt nhất hai nguồnCần chỉnh Kp/Ki phù hợp ứng dụng

Luồng xử lý 4 bước


  [1] Chuẩn hóa accelerometer
      acc_norm = acc / |acc|        (acc_norm là unit vector chỉ hướng trọng lực)

  [2] Ước lượng hướng trọng lực từ quaternion hiện tại
      v = R(q) × [0, 0, 1]         (vector "xuống" theo hệ body)
      Dùng hàng 3 của rotation matrix: rMat[2][0..2]

  [3] Tính sai số → hiệu chỉnh gyro
      error = acc_norm × v          (cross product → vector sai lệch)
      gyro_corrected = gyro + Kp×error + Ki×∫error·dt

  [4] Tích phân quaternion
      halfT = dt × 0.5
      q̇ = q ⊗ [0, gyro_corrected]  (quaternion kinematics)
      q = normalize(q + q̇ × halfT)

/* ── mahony_filter.c — Bước 2+3+4 ──────────────────────── */
void mahony_update(struct MAHONY_FILTER_t *m) {

    /* Bước 1: Chuẩn hóa acc */
    float norm = sqrtf(m->acc.x*m->acc.x + m->acc.y*m->acc.y + m->acc.z*m->acc.z);
    if (norm < 1e-6f) return;  /* tránh chia cho 0! */
    m->acc.x /= norm;  m->acc.y /= norm;  m->acc.z /= norm;

    /* Bước 2: Vector trọng lực từ rotation matrix hàng 3 */
    /* rMat[2] = hướng "xuống" trong body frame */

    /* Bước 3: Cross product = sai số góc */
    float ex = m->acc.y * m->rMat[2][2] - m->acc.z * m->rMat[2][1];
    float ey = m->acc.z * m->rMat[2][0] - m->acc.x * m->rMat[2][2];
    float ez = m->acc.x * m->rMat[2][1] - m->acc.y * m->rMat[2][0];

    /* Tích phân (I term) */
    m->exInt += m->Ki * ex * m->dt;
    m->eyInt += m->Ki * ey * m->dt;
    m->ezInt += m->Ki * ez * m->dt;

    /* Hiệu chỉnh gyro bằng PI */
    m->gyro.x += m->Kp * ex + m->exInt;
    m->gyro.y += m->Kp * ey + m->eyInt;
    m->gyro.z += m->Kp * ez + m->ezInt;

    /* Bước 4: Tích phân quaternion */
    float halfT = m->dt * 0.5f;
    float q0 = m->q0, q1 = m->q1, q2 = m->q2, q3 = m->q3;
    m->q0 += (-q1*m->gyro.x - q2*m->gyro.y - q3*m->gyro.z) * halfT;
    m->q1 += ( q0*m->gyro.x + q2*m->gyro.z - q3*m->gyro.y) * halfT;
    m->q2 += ( q0*m->gyro.y - q1*m->gyro.z + q3*m->gyro.x) * halfT;
    m->q3 += ( q0*m->gyro.z + q1*m->gyro.y - q2*m->gyro.x) * halfT;

    /* Chuẩn hóa quaternion */
    norm = 1.0f / sqrtf(m->q0*m->q0 + m->q1*m->q1 + m->q2*m->q2 + m->q3*m->q3);
    m->q0 *= norm;  m->q1 *= norm;  m->q2 *= norm;  m->q3 *= norm;
}

🐛Debug lỗi IMU thực tế

Triệu chứng: Board đặt phẳng trên bàn, /euler nhảy giữa −47° và +133° liên tục. Gyro và accel đọc đúng. Vậy lỗi ở đâu?

Root cause: dt đầu tiên = 3–10 giây


  t=0            t≈3-10s           t≈3-10s+1ms
   │                │                   │
  DWT_Init(550)  RTOS start         INS_task loop 1
  CYCCNT = 0     (sau init chip)    DWT_GetDeltaT(&INS_DWT_Count)
                                    = (CYCCNT - 0) / 550MHz
                                    = (≈1,650,000,000 - 0) / 550,000,000
                                    = 3.0 GIÂY  ← !!

  halfT = dt * 0.5 = 1.5 giây
  q += (...gyro_noise...) * 1.5
     = tiny_noise × 1,500,000 µs  ← quaternion bị thổi bay!

Fix đúng — 2 dòng thay đổi


void INS_task(void)
{
    INS_Init();

    /* ✅ Reset timer ngay trước vòng lặp.
       Dù BMI088 init mất bao lâu,
       dt đầu tiên sẽ chỉ là vài µs (thời gian chạy INS_Init). */
    DWT_GetDeltaT(&INS_DWT_Count);

    while(1)
    {
        ins_dt = DWT_GetDeltaT(&INS_DWT_Count);

        /* ✅ Safety cap: nếu vì lý do gì dt > 10ms → dùng 1ms.
           Tránh trường hợp bị preempt lâu bất thường. */
        if (ins_dt > 0.01f) ins_dt = 0.001f;

        mahony.dt = ins_dt;
        BMI088_Read(&BMI088);
        mahony_update(&mahony);
        osDelay(1);
    }
}

Checklist debug IMU

  1. Kiểm tra accel.z khi board phẳng
    ros2 topic echo /imu --once → linear_acceleration.z ≈ 9.81. Nếu = 0 → AccelScale = 0 → BMI088_init chưa được gọi đúng.
  2. Kiểm tra gyro khi đứng yên
    angular_velocity.x/y/z phải < 0.05 rad/s. Nếu lớn hơn → sensor noise hoặc offset chưa apply.
  3. Chờ ins_flag = 1 (3 giây)
    Euler chỉ valid khi ins_time > 3000. 3 giây đầu filter chưa hội tụ — bình thường.
  4. Kiểm tra dt có đều không
    Thêm snprintf(buf, ..., "dt=%.4f\r\n", ins_dt) in qua UART. Phải ≈ 0.001 mọi lúc.

Vòng lặp publish @ 50 Hz

for (;;) {
    /* Xử lý subscriber (non-blocking) */
    rclc_executor_spin_some(&executor, RCL_MS_TO_NS(10));

    uint32_t now = HAL_GetTick();
    if ((now - last_pub_ms) >= 20U) {     /* 20ms = 50 Hz */
        last_pub_ms = now;

        /* /imu — quaternion + gyro + accel */
        imu_msg.orientation.w         = (double)INS.q[0];
        imu_msg.orientation.x         = (double)INS.q[1];
        imu_msg.orientation.y         = (double)INS.q[2];
        imu_msg.orientation.z         = (double)INS.q[3];
        imu_msg.angular_velocity.x    = (double)INS.Gyro[X];
        imu_msg.linear_acceleration.x = (double)INS.Accel[X];
        /* ... Y, Z tương tự ... */
        rcl_publish(&pub_imu, &imu_msg, NULL);

        /* /euler — Roll/Pitch/Yaw (degrees) */
        euler_msg.x = (double)Roll_deg;
        euler_msg.y = (double)Pitch_deg;
        euler_msg.z = (double)Yaw_deg;
        rcl_publish(&pub_euler, &euler_msg, NULL);

        /* /motor_fb — position + velocity từ CyberGear */
        CAN_MotorFeedback_Get(&m_pos, &m_vel, &m_id, &m_valid);
        js_pos[0] = (double)m_pos;
        js_vel[0] = (double)m_vel;
        rcl_publish(&pub_motor_fb, &motor_fb_msg, NULL);

        /* /odom — dead-reckoning pose + Kalman velocity */
        float yaw = atan2f(2.0f*(INS.q[0]*INS.q[3] + INS.q[1]*INS.q[2]),
                            1.0f - 2.0f*(INS.q[2]*INS.q[2] + INS.q[3]*INS.q[3]));
        odom_x += Observe.v_filter * cosf(yaw) * 0.02f;
        odom_y += Observe.v_filter * sinf(yaw) * 0.02f;
        odom_msg.pose.pose.position.x    = (double)odom_x;
        odom_msg.pose.pose.position.y    = (double)odom_y;
        odom_msg.pose.pose.orientation.w = (double)INS.q[0];
        odom_msg.pose.pose.orientation.x = (double)INS.q[1];
        odom_msg.pose.pose.orientation.y = (double)INS.q[2];
        odom_msg.pose.pose.orientation.z = (double)INS.q[3];
        odom_msg.twist.twist.linear.x    = (double)Observe.v_filter;
        odom_msg.twist.twist.angular.z   = (double)Observe.omega_filter;
        rcl_publish(&pub_odom, &odom_msg, NULL);
    }
}

ROS_DOMAIN_ID là gì?

DDS chia thành 232 "domain" độc lập. Domain 0 là default, nhưng nếu bạn ở lab/văn phòng có nhiều nhóm dùng ROS 2, các topic sẽ xen vào nhau. Chọn một số riêng (1–101) cho project của bạn để tránh nhiễu.
